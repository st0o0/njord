## Context

Existing enforcement patterns: `EnumConversionArchitectureSpec` and `MappingConventionArchitectureSpec` scan production source text with allow-lists and negative self-tests; `DisabledTestArchitectureSpec` reflects over test assemblies; `TestTimeoutsSpec` pins timeout constants. Roslyn analyzers are not used in this repo (`TreatWarningsAsErrors` off, no analyzer packages), and `xUnit1069` is the only test-related analyzer set to error.

## Goals / Non-Goals

**Goals:** convert the mechanically checkable test conventions into failing specs; keep the review-only rules explicit.

**Non-Goals:** introducing Roslyn analyzers or `TreatWarningsAsErrors`; checking semantic rules (vacuous assertions, assert-the-exact-value) that need human judgement.

## Decisions

1. **Source scanning, not analyzers.** A shared `TestSourceScanner` in `Njord.Architecture.Tests` enumerates `src/Njord.*Tests/**/*.cs`, strips comments and string literals, and matches patterns with small tokenizers. This follows the existing production-code scans and avoids a new analyzer package. Method-level facts (async plus attribute list) use a light parser over attribute lists and signatures.
2. **One rule per theory row.** The spec is a `[Theory]` over rule definitions (name, pattern, allow-list), so a new rule is one row, and failures name the rule.
3. **Allow-lists start from the current state and shrink.** Applied after `test-gaps-and-drift`, the lists should contain only the cancellation-bound infinite delays in Mqtt fake transports and the documented `!.` deviations. Every entry carries a reason; stale entries fail the spec.
4. **Options rule limited to types with shipped defaults.** The set of such types is derived from the default-options golden master (`DefaultOptionsSpec`), so adding an option with defaults extends the rule automatically.
5. **Doc-reference spec reads text files.** It extracts backticked identifiers and paths from `AGENTS.md` and skills, and checks them against exported symbols of `Njord.Tests.Shared` and file names; unknown identifiers that are clearly not code (framework names, domain terms) are skipped with an ignore list kept next to the spec. The test count check discovers tests by reflection on `[Fact]`/`[Theory]` attributes (theory rows counted from `InlineData`/`MemberData` where statically countable, otherwise one) and documents the counting rule next to the number in `AGENTS.md`.
6. **Review-only rules stay review-only.** Vacuous-assertion and exact-value rules are labelled as such in `AGENTS.md`.

## Risks / Trade-offs

- Text scanning can produce false positives (strings containing `UtcNow`); mitigated by stripping literals/comments, negative self-tests and the allow-list.
- The count check can drift on theory rows; the counting rule is explicit and the number in `AGENTS.md` is generated by the same rule, with a failure message printing the expected value for a copy-paste fix.

## Migration Plan

No operator impact. Order: scanner and self-tests, the rules one by one with allow-lists, doc-reference spec, `AGENTS.md` labels.
