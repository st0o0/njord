## Context

See proposal.md. `Njord` is a single assembly, so zones are namespaces, not projects. `Njord` exposes internals to `Njord.Tests` (`InternalsVisibleTo`). FunkArr uses `TngTech.ArchUnitNET.xUnitV3` 0.13.4 in a separate `FunkArr.Architecture.Tests` project because it has ~11 assemblies to assert reference direction between.

Zone mapping used by the rules:

| Zone | Namespaces |
|---|---|
| Ingest | `Njord.Ingest` |
| Domain | `Njord.Domain.{Weather,Sensors,Analysis}` |
| Egress side | `Njord.Egress`, `Njord.Mqtt` (+ `.Transport`), `Njord.Grpc` |
| Orchestration / shared | `Njord.Pipeline`, `Njord.Enrichment`, `Njord.Actors`, `Njord.Sensors`, `Njord.Persistence`, `Njord.Configuration`, `Njord.Diagnostics`, `Njord.Health` |

## Goals / Non-Goals

**Goals:** enforce Ingest↔Egress independence and Domain independence at test time; enforce sealed/Spec conventions while it is cheap.

**Non-Goals:** rules for orchestration/shared namespaces; transitive-dependency analysis; Akka conventions (see proposal Non-goals).

## Decisions

### 1. Current state: zero violations (verified by `using` and type grep)

- `Njord.Ingest` uses `Njord.Configuration`, `Njord.Domain.Weather`, `Njord.Diagnostics` only.
- `Njord.Egress` uses `Njord.Domain.Weather`, `Njord.Pipeline`, `Njord.Configuration`, `Njord.Actors`; no `Njord.Ingest`.
- `Njord.Mqtt` uses Egress, Pipeline, Enrichment, Domain, Configuration, Health, Diagnostics, Actors; no `Njord.Ingest`.
- `Njord.Grpc` uses Pipeline, Persistence, Egress, Sensors, Domain, Configuration, Actors; no `Njord.Ingest`.
- `Njord.Domain.*` uses only `Njord.Domain.Weather` and `Njord.Configuration`; no Ingest/Egress/transport.
- Sealed: no non-sealed, non-abstract production class. Tests: every class with `[Fact]`/`[Theory]` is `sealed` and in a `*Spec.cs` file.

Caveats that shape the rules:
- Indirect path exists and is allowed: `Egress → Pipeline → Ingest`. Pipeline is the orchestrator that legitimately talks to Ingest; the rule is direct dependency only.
- `Domain → Njord.Configuration` exists (3 files) and `Njord.Configuration` references most zones (Options/validators). The Domain rule therefore forbids only Ingest/Egress/transport namespaces, not Configuration. Tightening that is a separate decision.
- Because there are no current violations, no allow-list is needed. If a future violation is unavoidable, the fix is to move the shared type into `Njord.Domain.*`, not to add an allow-list entry; the tests carry no allow-list.

### 2. ArchUnitNET over NetArchTest or hand-rolled reflection

- **ArchUnitNET (chosen):** analyzes IL dependencies including field/method-body references, fluent namespace rules, and failure messages naming offender and dependency. Same package/pattern as FunkArr (`TngTech.ArchUnitNET.xUnitV3`), so conventions carry over.
- **NetArchTest:** simpler API but weaker on dependency detail and less maintained. Rejected.
- **Hand-rolled reflection:** only sees signatures (fields, parameters, base types), misses method-body dependencies, and needs bespoke failure reporting. Rejected.

### 3. Folder in `Njord.Tests`, not a separate project

`src/Njord.Tests/Architecture/`. FunkArr splits because it asserts across assemblies; njord has one production assembly, so a separate project would add a csproj, slnx entry and CI wiring for no isolation benefit. The test loads the `Njord` assembly through `ArchLoader` using a type from it (e.g. `typeof(Njord.Ingest.OpenMeteoClient).Assembly`); `InternalsVisibleTo` does not affect loading. *Revisit if* a second production assembly appears.

### 4. Shared architecture instance, namespace-based layers

One static `ArchUnitNET.Domain.Architecture` per test class (loading is the slow part), layers defined with `ResideInNamespace` patterns from the zone table. Test class `ZoneArchitectureSpec` (sealed, `Spec` suffix) holds the zone rules; `ConventionArchitectureSpec` holds sealed/Spec rules. Tests follow repo style (`[Fact(Timeout = 5000)]` where the ArchUnit attribute style permits; check at implementation whether `[Fact(Timeout=...)]` applies to ArchUnit-loaded static init — loading may need a larger timeout, documented in the test).

### 5. Test-class convention rule scope

The rule inspects `Njord.Tests` types that declare methods with xUnit `FactAttribute`/`TheoryAttribute`. Helpers/fixtures/fakes are exempt (e.g. `TestServerCallContext`, `ModuleInitializer`). Auto-generated `XunitAutoGeneratedEntryPoint` is excluded.

## Risks / Trade-offs

- [ArchUnit load time slows test run] → one shared architecture per class; only the `Njord` and `Njord.Tests` assemblies loaded.
- [`[Fact(Timeout = 5000)]` too tight for assembly loading] → measure in the red/green step; if needed use a documented larger timeout for these specs only.
- [False sense of safety from direct-only rule] → documented in Decision 1; transitive analysis is a Non-goal.
- [Rules too strict for future legit needs] → move shared types into Domain rather than weakening rules.
- [Package version mismatch with xunit.v3.mtp-v2] → add via `dotnet add package`; verify the run before committing (FunkArr uses the same combination).

## Migration Plan

Test-only addition; no runtime change. Rollback: delete the folder and package reference.
